GUI Desktop Manual

This manual provides a detailed breakdown of the functionality found inside the DigiQual Shiny application. For instructions on how to install or launch the app, see the Launch the App guide.

The DigiQual app is a guided workflow and a visual alternative to the Python API. It follows the same steps as the Quick Start; the statistics behind each step are explained in Generalised PoD.

1 Finding Your Way Around

1.1 Start page

The app opens on a start page with two ways in: Plan simulations (go to Simulation Design and build a design to run in your solver) or Analyse results (go straight to Data Diagnostics with results you already have). Below them, The workflow gives an overview of the five stages.

1.2 Header

DigiQual and Home return to the start page. About opens a separate page with the version, links, methodology papers, funders and the disclaimer. Reset clears everything and starts again (after a confirmation).

1.3 Stages:

The analysis is split into five stages, shown one at a time:

  1. Simulation Design: plan the runs (optional).
  2. Data Diagnostics: upload the results and check they are sufficient.
  3. Model Diagnostics: choose the surrogate model and check its fit.
  4. Model Explorer: decide how the model becomes a PoD, and explore it.
  5. PoD Analysis: add confidence bounds, read off aX/Y values and export.

Every stage has the same layout: its settings in a sidebar on the left, its results on the right (with tabs when there is more than one view), and Back / Next buttons at the bottom.

1.4 The stepper

The bar under the header shows every stage with its status and a one-line summary of what was decided there (for example 250 rows · 2 inputs, Poly 1 · R² 0.83, a90/95 = 7.244). Click any stage to go to it. The stepper is hidden on the start and About pages.

Status Meaning
Green tick Done
Amber warning Done, but with a problem worth a look (failed data checks, model R² below the threshold)
Amber arrows Out of date: something earlier changed (e.g. re-run checks, update needed)
Grey circle Ready to do
Spinner A background task is running: fitting models…, computing PoD… or bootstrap running…
Faded, with a lock Waiting for an earlier stage; opening it explains what’s missing

2 Simulation Design

Purpose: Generate a statistically sound set of sampling points for your physics solver to evaluate. This stage is optional.

  1. Add Variables: Click “Add Variable” for each continuous parameter in your simulation (e.g., Length, Angle) and set its minimum and maximum. The design covers these ranges evenly.
  2. Number of runs: Enter the total number of simulation runs you plan to execute (\(N\)).
  3. Generate Design: The tool builds a space-filling Latin Hypercube design. The rows are ordered so that any first \(k\) of them are also well spread, so you can run the simulations in order and stop early (how this works).
  4. Download CSV: Save generated_sample.csv and feed it into your external solver (e.g., MATLAB, Abaqus, ANSYS) to calculate the signal responses.

3 Data Diagnostics

Purpose: Upload your results and check they are sufficient to model: coverage of the inputs, a learnable signal, stability, and correlated inputs.

  1. Upload Data: Upload the CSV containing your completed simulation results, one row per run. The file is cleaned the same way as digiqual.io.read_results_csv:

    • column names are trimmed, spaces become underscores and other special characters are removed;
    • duplicate names are numbered (e.g. a second Signal becomes Signal_1);
    • text columns are dropped, with a warning, and completely empty columns (e.g. from trailing commas) are dropped quietly;
    • stray text cells in a numeric column become missing values, with a warning, and those rows are left out when the data is validated.

    The file needs at least two numeric columns.

  2. Choose Columns: Select the input variables and the outcome (the signal response). By default the last column is the outcome and all the others are inputs.

  3. Run Diagnostics: The engine runs the five diagnostic tests (input coverage, model fit, two bootstrap-stability checks and collinearity). What each test measures and its default threshold are listed in Sampling & Diagnostics. The thresholds can be changed under Diagnostic thresholds; doing so marks the results as out of date until you run the diagnostics again, but keeps the fitted model.

  4. Status and remediation: The result card shows whether all checks passed. If the coverage, model fit (CV) or bootstrap stability checks fail, it includes a Fix it with more runs box: set Samples per issue and press Generate New Samples to create new runs targeted at the gaps and unstable regions, then download them as remediation_samples.csv. Run them in your solver and upload the combined results. A collinearity failure can’t be fixed by adding runs; remove or decouple the correlated inputs instead.

  5. Views: Report (test results, summary statistics and a preview of the data), Variables (distribution of each variable, or each input against the outcome, with any coverage gap shaded), Coverage (all inputs at once) and Collinearity (correlation heatmap with VIF values).

4 Model Diagnostics

Purpose: Choose the surrogate model of the signal response and check how well it fits.

4.1 Run models

Until the data diagnostics have run, this stage only says Run the data diagnostics first., and the stepper shows it locked. After that, it explains what fitting involves and offers a large Run models button. Pressing it fits every candidate model once for the dataset:

  1. Cross-validation: Polynomials (degrees 1–10) and Kriging are each scored by 10-fold cross-validation (Kriging is skipped above 1000 runs).
  2. Scatter model: how the spread of the signal around the model changes across the inputs, and which distribution describes it.
  3. Sensitivity: total-order Sobol indices.

This takes from a few seconds to a minute, depending on the data. The fit runs in the background: a progress panel shows each step, the candidate being scored (e.g. Polynomial, degree 4 (4 of 15)) and the elapsed time. The stepper shows fitting models…, and you can look at other stages meanwhile. When it finishes, the page switches to the model views below; you never need to run it again for this dataset. The models are always trained on all input variables, so nothing here depends on which variables you later plot, integrate over or slice.

4.2 Sidebar

The Model dropdown starts at “Auto”, which picks the simplest model within one standard error of the best (how the choice is made). Pick any other candidate instead. The candidates are already cross-validated and fitted, but the chosen model still needs its scatter model and Sobol indices, so the change runs in the background with a Fitting the chosen model progress panel (quicker for a model you have used before). A choice made while a fit is running is applied when that fit finishes. Below it are the model’s cross-validated \(R^2\) (green if it passes the threshold from Data Diagnostics) and the parameter sensitivity: total-order Sobol indices, including interactions.

4.3 Views

  • Model selection: the cross-validation error of every candidate, marking the automatic choice and the one you picked.
  • Fit quality: actual vs predicted (in-sample for polynomials, leave-one-out for Kriging; pass/fail on the 10-fold cross-validated \(R^2\)) and a bootstrap convergence trace, judged against the thresholds from Data Diagnostics.
  • Kriging residuals (Kriging only): the standardised leave-one-out residuals, to spot outliers or an over-smooth kernel.
  • Equation & statistics: the fitted equation (polynomials) and the fit statistics.

If Data Diagnostics found issues, they are listed above the views.

5 Model Explorer

Purpose: Decide how the multi-dimensional model is turned into a PoD, and explore it in real time.

The sidebar holds the chosen model (with a link back to change it), the Detection Threshold and the Update PoD button. Above the plots, the PoD setup table has one row per input variable: its range, its role (chosen with the Plot / Integrate / Slice buttons) and the settings for that role, on one line:

Role What it means Controls
Plot On the x-axis (1 variable: PoD curve) or one of two axes (2 variables: PoD surface) None: the full data range is used
Integrate Averaged out by Monte Carlo integration (at most 2) Distribution (Uniform, Normal, Lognormal or Weibull, fitted to the data) and the range (from, to)
Slice Held at a fixed value A slider plus a box for an exact value

The roles start with the most influential input (highest Sobol index) plotted and the rest sliced at their medians. Exact values are shown and used to 3 decimal places (more only for variables with a very small range). Problems such as no plotted variable or an empty integration range are shown above the Update PoD button.

Under the table, a note for each integrated variable says what will be used: for a fitted distribution its parameters (e.g. μ and σ for Normal) and the range holding 95% of its values, and the range sampled, marked limited to the data range if you typed limits outside the data. If a distribution can’t be fitted, for example Lognormal or Weibull for a variable with values ≤ 0, the note says so and Uniform is used instead.

  1. Update PoD: After changing the model, which variables are plotted or integrated, or a distribution or integration range, press Update PoD. It computes the PoD and a 100-threshold spectrum (caching details). This runs in the background: a progress panel shows each step in place of the plots, and the stepper shows computing PoD….
  2. Slices and threshold (live): Moving a slice or the Detection Threshold (slider or exact value) updates the plots immediately. The slider is for quick moves; type a value for an exact one. Integration ranges are limited to the observed data, because the model can’t be trusted outside it.
  3. Plots: the signal model (left) and the PoD curve or surface (right).

6 PoD Analysis

Purpose: Add bootstrap confidence bounds to the PoD from the Model Explorer, read off reliability indices and export the results.

  1. Analysis setup: The sidebar summarises the settings the analysis uses (model, plotted, integrated and sliced variables, threshold), with a link back to edit them in the Model Explorer.

  2. Run Bootstrap: Set Iterations (default 1000, minimum 10) and Parallel compute (faster) (on by default; it uses all but two of your CPU cores), then press Run Bootstrap. The data is resampled and the chosen model’s shape refitted many times to build the bounds (bootstrap details); the bounds reflect parameter uncertainty assuming that shape is correct. The bootstrap runs in the background: a progress panel shows the iterations completed and the elapsed time, the stepper shows bootstrap running…, and you can look at other stages meanwhile.

  3. Reliability targets: Choose a Target PoD (%) (50, 90, 95, 99) and a Confidence (%) (50, 90, 95, 99) to annotate the curve with the matching sizing point (e.g., a90/95). Changing them does not rerun the bootstrap.

  4. Results: the PoD curve with confidence bounds, PoD against the detection threshold, the Reliability Index Matrix (aX/Y for every combination of Target PoD and Confidence Level) and the selected metric. With two plotted variables the PoD is a surface, so there are no aX/Y sizes or PoD-vs-threshold plot: you get the PoD surface and a Run Summary card instead. After a bootstrap the Model Explorer plots also show the confidence bounds, until a slice, the threshold or another setting changes.

  5. Out-of-date results: If you change the model or explorer settings after running the bootstrap, the results are kept but marked as out of date (also in the stepper) until you run it again.

  6. Export: the export button appears once a bootstrap has run.

    • Excel Report: digiqual_pod_report.xlsx, with sheets for the model (statistics and equation), the analysis setup, the UQ metrics, the PoD curve data and the reliability matrix.

The report describes the analysis the bootstrap actually ran (model, setup, threshold and iterations), even if you have changed settings since. Target PoD and Confidence don’t change the bootstrap, so the report uses the values selected when it ran: its UQ Metrics sheet reports that aX/Y (all combinations are in its Reliability Matrix sheet).
